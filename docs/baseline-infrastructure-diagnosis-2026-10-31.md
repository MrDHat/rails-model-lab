## Confirmed namespace incompatibility

An offline disposable container reproduced the retained `unshare: pidfd_open failed: Function not implemented` error using the namespace command from lemans 1.5.1. The failing task image is amd64; this Docker host is ARM64. An existing ARM64 image passes the identical command. This establishes a compatibility failure on the emulated-image path. It does not establish that all setup failures have that cause. A compatible native x86 environment or a separately validated runtime repair is still needed for that image.

`experiments/check-local-jail.py` repeats this narrow probe using existing images only, with no network and no model or task inputs. It is not a full agent-jail or verifier validation.

This validates the native synthetic path, not the failing pinned amd64 image or every benchmark environment.

## Local sleep and remote lifecycle

The local power log records clamshell sleep at 01:20:35 UTC despite an active caffeinate assertion. The remote log records cancellation at 01:22:37 and says the local client disconnected. The first subsequent local heartbeat failure was logged at 01:34:18, shortly after a dark wake.

This timing strongly supports laptop suspension interrupting the client heartbeat. It is not a reproduction of Modal's server-side disconnect decision. [Modal documents](https://modal.com/docs/guide/apps) that an attached ephemeral app stops when the client disconnects; [detached runs](https://modal.com/docs/cli/latest/run) survive client disconnection. Detaching inference alone would not keep a local benchmark harness executing while its host sleeps.

The prospective controller now requests detached mode and explicitly stops its exact app after started trials settle, recording the stop command's outcome and flagging any stop failure in the completion event. The existing independent remote absolute deadline remains unchanged. Simulated lifecycle tests cover detached selection, explicit shutdown after a shared fault, and reporting a failed shutdown. These simulated checks alone establish controller behavior, not remote reliability. Local harness suspension remains unresolved.

A subsequent CPU-only lifecycle probe did validate the basic remote mechanism: its client forcibly exited without graceful cleanup while a call was active; the detached call completed after 150 seconds, a separate client retrieved the result, and explicit stop plus the exact app lifecycle confirmed shutdown. The returned source hash matches the local probe source. No GPU or benchmark task was invoked. This does not validate Qwen inference, expired-token renewal, local harness suspension, or a full benchmark-duration connection.

## Remote runner budget gate

A VM runner needs a separate compute reservation. [Modal prices Sandbox CPU and memory at non-preemptible rates](https://modal.com/pricing), approximately three times ordinary Function rates. The current $1.50/hour local-harness reservation does not include that remote CPU runner and must not be reused for a VM launch.

Reading the pinned harness configuration produced an offline resource inventory without executing tasks. A conservative continuous-resource bound exceeds the $25 ceiling for three long multistep tasks even when run individually. This is an upper-bound planning limitation, not measured task cost or evidence that free execution is impossible. Native VM CPU quota mapping and disk capacity, plus accounting for GPU scale-down during build/verification phases, still need validation before a remote full-allowance plan can be admitted.
